# Nova-Interactions Command Reference

This document explains every player command in Nova-Interactions, what each command does, when to use it, and example usage.

## Command Overview

- `/interact <interactionName>`: Sends a simple interaction request to the nearest player.
- `/interact hostage`: Attempts to take the nearest player hostage.
- `/hostage`: Shorthand command for hostage interaction.
- `/ia`: Accepts a pending interaction request.
- `/id`: Declines a pending interaction request.
- `/interactions`: Lists all available simple interaction names.

## Interaction Flow

Simple interaction flow (handshake, hug, etc.):
1. Player A sends a request with `/interact <interactionName>`.
2. Player B receives a request notification in chat.
3. Player B accepts with `/ia` or declines with `/id`.
4. If accepted, both players play synchronized interaction animations.

Hostage flow:
1. Aggressor runs `/interact hostage` or `/hostage` near a target.
2. If valid, the target is attached and held hostage.
3. Aggressor can release or execute using configured keys.

## Detailed Commands

### 1. /interact <interactionName>

Purpose:
- Sends a consent-based simple interaction request to the nearest player.

Syntax:
- `/interact <interactionName>`

Parameters:
- `<interactionName>`: One of the generated simple interaction keys from config.

What it does:
- Finds nearest player within simple interaction distance.
- Sends a server-validated interaction request.
- Target can accept with `/ia` or decline with `/id`.

Examples:
- `/interact handshake`
- `/interact warm_hug`
- `/interact nova_wave_style`

Notes:
- If no nearby player is found, request is not sent.
- If interaction name is invalid, chat prompts you to use `/interactions`.
- Request cooldown and timeout are controlled by config values.

### 2. /interact hostage

Purpose:
- Starts advanced hostage interaction against nearest player.

Syntax:
- `/interact hostage`

What it does:
- Checks hostage feature enabled.
- Checks that aggressor is holding an allowed weapon.
- Finds nearest player within hostage distance.
- Server validates state and starts hostage mode on both players.

Notes:
- Requires configured weapon from Config.Hostage.requiredWeapons.
- Cannot start if either player is already in a hostage state.

### 3. /hostage

Purpose:
- Quick alias for hostage interaction.

Syntax:
- `/hostage`

What it does:
- Runs the same logic as `/interact hostage`.

When to use:
- Use this as a faster command during roleplay scenarios.

### 4. /ia

Purpose:
- Accepts an incoming simple interaction request.

Syntax:
- `/ia`

What it does:
- Accepts current pending request if still valid.
- Triggers synchronized animations for both players.

Notes:
- Works only when you have a pending request.
- Requests can expire if timeout has passed.

### 5. /id

Purpose:
- Declines an incoming simple interaction request.

Syntax:
- `/id`

What it does:
- Declines pending request.
- Notifies the requesting player.

Notes:
- Works only when you have a pending request.

### 6. /interactions

Purpose:
- Displays all available simple interaction names currently generated by config.

Syntax:
- `/interactions`

What it does:
- Prints total interaction count.
- Prints interaction names in multiple chunked chat messages.
- Also reminds players of other utility commands.

When to use:
- Use this to discover valid names for `/interact <interactionName>`.

## Hostage Controls

Default key behavior while aggressor is holding hostage:
- Release hostage: `G`
- Execute hostage: `H`

Where to configure:
- Config.Hostage.controls in config.lua.

## Common Chat Messages and Meanings

- `Usage: /interact <interactionName> | /interact hostage`
  - You ran /interact with no argument.

- `Unknown interaction: <name>`
  - The interaction key does not exist in generated list.

- `No player nearby for that interaction.`
  - No target found within configured interaction distance.

- `No player nearby to take hostage.`
  - No target found within hostage distance.

- `You must hold a configured pistol to take a hostage.`
  - Your current weapon is not in allowed hostage weapon list.

## Configuration Pointers

Relevant config keys that affect command behavior:
- Config.DefaultInteractDistance
- Config.RequestTimeoutMs
- Config.RequestCooldownMs
- Config.SimpleInteractions (generated set)
- Config.Hostage.enabled
- Config.Hostage.interactionDistance
- Config.Hostage.requiredWeapons
- Config.Hostage.controls.release
- Config.Hostage.controls.execute

## Quick Start for Players

1. Run `/interactions` to see valid interaction names.
2. Pick one and use `/interact <interactionName>` near another player.
3. Target player responds with `/ia` or `/id`.
4. For high-risk RP situations, use `/hostage` when conditions are met.

## Admin Testing Checklist

- Verify /interactions prints expected large interaction list.
- Verify invalid names fail gracefully.
- Verify request timeout and cooldown behavior.
- Verify hostage requires valid weapon.
- Verify release and execute controls work as configured.
- Verify disconnect cleanup ends hostage state.
